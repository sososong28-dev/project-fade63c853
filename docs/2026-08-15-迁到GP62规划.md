# 咸鱼项目迁到远端 GP62 — 规划

日期：2026-08-15  
目标：把本机整套闲鱼自动化（上架/客服/自动发货/巡检）收到远端 MSI GP62 上长期跑。  
原则：先复制能跑，再切流；切流当天只停本机 WebSocket，避免双开踢号。

## 1. 现在这套到底有什么

| 层 | 现状 | 迁过去必须带 |
|---|---|---|
| 主栈 | Docker：mysql / redis / backend-web:8089 / websocket:8090 / scheduler:8091 / frontend:9000 | 要。优先拉阿里云现成镜像，不要在 GP62 源码 `--build`（本机已因清华 PyPI SSL 失败过） |
| 业务数据 | MySQL 卷里的账号 Cookie、卡券、关键词、AI 配置、发布日志 | **必须 dump**，只拷代码会空库 |
| 运维脚本 | `D:\咸鱼自动化\scripts\`、`config\`、计划任务 `Xianyu_PathHealth_4x`（每天 9/12/15/18） | 要。任务在 GP62 重注册 |
| 过滑块 | 本机 Python `scripts/win-real-mouse-captcha` 监听 **18900**，要真实桌面鼠标 | 要。GP62 必须 Windows + 已登录桌面，不能只跑无界面服务 |
| 上传包/封面 | `config\*.png`、`upload-packs\` | 建议带 |
| 可不搬 | `scripts\win-real-mouse-captcha\.venv`（到 GP62 重建）、`怪物猎人存档研究包`（约 1.1GB，与值班无关）、本机 Docker 构建缓存 | 先不搬 |
| 旁路资料 | `D:\游戏攻略\` 的 PDF | 上架素材，不在主栈里；要继续手动上架再另拷或继续用网盘 |

体积粗算：有效代码+配置约 **1.8GB**（不含存档研究包、不含 venv）。Docker 镜像另占约 **数 GB**，GP62 建议空余 **≥ 40GB**。

## 2. 推荐形态（与现在一致）

```
GP62 (Windows，长期开机、接电源、禁止睡眠)
├── Docker Desktop
│   └── xianyu-* 六个容器（数据从本机 mysqldump 恢复）
├── 本机进程：win-real-mouse-captcha :18900
├── 计划任务：Xianyu_PathHealth_4x
└── 远程桌面/向日葵/ToDesk：你日常看后台 http://127.0.0.1:9000
```

不要迁到 Linux/云主机：真实鼠标过滑块依赖 Windows 交互桌面。

## 3. 阶段

### P0 本机收口（切流前 1 天，约 30 分钟）

1. 确认本机健康：账号 WS `active`，`blockers=[]`。
2. 导出数据库（密码看 `xianyu-auto-reply\.env` 的 `MYSQL_ROOT_PASSWORD`）：

```powershell
docker exec xianyu-mysql mysqldump -uroot -p"密码" --databases xianyu_data --single-transaction --routines > D:\咸鱼自动化\backup-xianyu_data.sql
```

3. 打包要拷的目录（不要带 `.venv`）：
   - `xianyu-auto-reply\`（含 `.env`）
   - `scripts\`（可排除 `win-real-mouse-captcha\.venv`）
   - `config\`
   - `upload-packs\`
   - `.cursor\skills\`
   - `docs\`、`README.md`
4. 记下计划任务动作：`D:\咸鱼自动化\scripts\health-auto.cmd`

### P1 GP62 环境（一次，约 1–2 小时）

- Windows 长期登录；电源：接电 + 关闭睡眠/休眠；锁屏可，但过滑块时需要解锁的交互会话（向日葵挂着即可）。
- 安装：Docker Desktop（WSL2）、Python 3.11+、Node.js 18+、Chrome。
- 远程：ToDesk/向日葵/RDP 任选，**不要把 9000/8089 映射到公网**。
- 可选：装 Cursor，以后直接在 GP62 上改脚本。

### P2 落盘启动（约 1 小时，本机先不停）

1. 解压到 GP62 建议仍用 `D:\咸鱼自动化`，少改路径。
2. 启动主栈用**已有镜像**，不要 `--build`：

```powershell
cd D:\咸鱼自动化\xianyu-auto-reply
docker compose -f docker-compose.deploy.yml --env-file .env up -d
```

若 `deploy.yml` 与当前跑着的镜像 tag 不一致，就按本机正在用的 `registry.cn-shanghai.aliyuncs.com/zhinian-software/xianyu-*:latest` 起。

3. 等 mysql healthy 后导入 dump，再重启 backend/websocket/scheduler。
4. GP62 重建滑块 venv，用 `scripts\win-real-mouse-captcha\.env` 原样拷过去，开机启动 `server.py`。
5. 注册计划任务 `Xianyu_PathHealth_4x`（9/12/15/18），工作目录指向 GP62 上的 `health-auto.cmd`。

### P3 并行验收（本机仍值班）

在 GP62 上只验这些，**先不要 connect 账号**：

- `http://127.0.0.1:9000` 能开后台
- `node scripts/api-client.js health` 四项 200
- 登录后台能看到原卡券（27+）、账号 `413198903`、AI MiniMax 配置还在

### P4 切流（10 分钟窗口）

同一闲鱼账号不能两台同时 WS。

1. 本机：`node scripts/api-client.js enable-account 413198903 false`（或停 `xianyu-websocket`）
2. GP62：enable + connect，确认 `connected=true / active`
3. 本机计划任务禁用，避免两边巡检抢着重连
4. 用另一账号发一句非关键词闲聊，看 AI 是否回；拍测或看卡券绑定是否还在

失败则立刻在本机重新 enable+connect，GP62 断开。

### P5 本机收尾

- 本机 Docker 可停，保留 dump 一周再删。
- 本机不要再扫码登录同一账号。
- 日常只远程进 GP62。

## 4. 风险

| 风险 | 处理 |
|---|---|
| Cookie 迁过去后失效 | GP62 后台重新扫码；dump 只能保证「库还在」 |
| 两台同时连 | 切流脚本按 P4，先停本机 |
| GP62 睡眠/断网 | 接电 + 禁止睡眠；向日葵掉线不等于 Docker 停，但滑块会停 |
| 源码 build 失败 | 只用阿里云镜像 |
| 路径不是 D: | 改计划任务和少数脚本里的绝对路径 |
| 复活邪神那本 PDF 损坏 | 与迁移无关，上架包已注明 |

## 5. 你需要先定的两件事

1. **远程方式**：GP62 现在是向日葵 / ToDesk / 同一局域网，哪一种？决定我能不能直接在那台上操作。
2. **切流日**：建议先 P0–P3 周末做完，选一个买家少的晚上做 P4（10 分钟）。
