# 2026-08-18 WS 掉线与定时自愈 token 过期

## 现象

8/17 全天没有自动回复、没有自动发货。用户已手动补发。

## 事实

- 四个服务（backend-web / websocket / scheduler / frontend）一直在跑。
- 卖家账号 `413198903` 处于 `disabled`，WebSocket `connected=false`。
- 计划任务 `Xianyu_PathHealth_4x` 当天 4 次（约 9/12/15/18）全部 `reconnect_failed`。
- 重连接口返回 **401** `Could not validate credentials`。
- 巡检因此误报：账号数=0、WS missing、卡券未绑定、无发布日志。
- 本地订单库无 8/17 新单；最近自动回复停留在 8/9。同类掉线还出现在 8/12、8/14、8/15，token 有效时 8/13、8/16 能自动重连成功。

## 根因

1. 夜间 WebSocket 掉线后账号被置为 disabled。
2. 定时自愈只用磁盘里的 `scripts/.token` 调 enable/connect，**没有先刷新后台 JWT**。
3. token 过期 → 401 → 自愈空转一整天。

## 处理

- 8/18 手工 `login` → `enable-account` → `connect`，账号恢复 `active`。
- 未发货订单由用户手动补发。
- 改 `scripts/health-auto.js`：每次计划任务**先 login 再巡检**；WS 仍离线则 enable + connect。
- `scripts/patrol-path.js`：401 明确记为 token 失效，不再伪装成「账号数=0」。

## 以后怎么看

- 任务仍是 `Xianyu_PathHealth_4x`，入口未改，只改了脚本逻辑。
- 若 history 出现 `login_failed`：后台账号/密码或 8089 服务有问题。
- 若 login 成功仍 `reconnect_failed`：多半是闲鱼 Cookie 失效，走 `revive-account` 扫码。
