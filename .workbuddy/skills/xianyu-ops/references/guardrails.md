# 安全与输出约定

## 动作边界

当前 Skill 只允许：

1. 读取本地服务健康状态。
2. 调用公开商品搜索、会话读取、聊天记录读取和经营统计查询。
3. 在本地生成商品或回复草稿。

不允许发布、发送、删除、改价、上下架、发货、补发、启用、重连、重启等状态变更。后续新增这些能力时必须使用独立命令、显式确认、幂等键和审计日志，不得附加到现有只读命令中。

## 统一响应

成功：

```json
{
  "ok": true,
  "command": "doctor",
  "data": {},
  "warnings": [],
  "meta": {"mode": "live", "read_only": true, "external_writes": false}
}
```

失败时 `ok=false`，`error.code` 区分参数、认证、权限、网络、HTTP、业务响应和超时。项目部分接口以 HTTP 200 返回 `success=false`，CLI 会将其转换为业务失败，不得误报成功；其中 Token 失效统一返回 `AUTH_REQUIRED`，数据罗盘无权限统一返回 `PERMISSION_DENIED`。巡检必须检查 `/auth/verify` 正文中的 `authenticated=true`，不能仅凭接口请求成功就判定已认证，Token 无效时不得继续请求账号接口。

## 降级原则

- 巡检中单个服务失败不妨碍返回其他服务状态，但整体状态为 degraded。
- 日报中管理员今日统计或数据罗盘失败时，保留可用的本地统计并列出警告。
- 回复草稿读取不到聊天记录时可使用会话摘要，但必须给出警告。
- 不用模拟数据填充真实报告；只有显式 `--fixture` 才允许离线样例。

## 数据最小化

行情结果不输出原始接口响应和卖家个人信息；回复结果只保留当前买家问题、会话 ID 和商品标题；日报不输出收货人、联系方式、地址或交付内容。
